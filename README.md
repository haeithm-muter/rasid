# رصيد (Rasid)

كاشف الاشتراكات المنسيّة من كشف الحساب البنكي. يقرأ ملف CSV **داخل المتصفح
بالكامل** ويكشف الرسوم المتكررة المنسية. **صفر رفع بيانات لأي خادم.**

> هذا المستودع يحتوي حالياً **الجزء 1: التأسيس وطبقة الإدخال**، و**الجزء 2:
> محرك الكشف**. الواجهة ومرحلة التقييم (الجزء 3) لم تُبنيا بعد.

## العقد بين الأجزاء

كل شيء ينتهي إلى هذا النوع، وعليه يبني الجزءان 2 و3:

```ts
type Transaction = {
  date: string;        // ISO صارم: YYYY-MM-DD
  description: string; // الوصف الخام كما ورد (بلا تنظيف)
  amount: number;      // موجب دائماً
  currency: string;    // ISO-4217 بحروف كبيرة
  direction: 'debit' | 'credit';
};
```

نقطة الدخول الموحّدة:

```ts
import { importCsvBytes } from './src/core/importCsv';

const { transactions, skipped, adapter, encoding } = importCsvBytes(bytes);
```

`skipped` يحمل كل صف تعذّر تحويله مع سبب مقروء بالعربية — الملف لا يفشل كاملاً
بسبب صف واحد تالف.

## إضافة بنك جديد

**ملف واحد جديد، بلا تعديل أي كود قائم.** أنشئ
`src/adapters/<اسم-البنك>.adapter.ts`:

```ts
import { createBankAdapter } from './createBankAdapter';

export default createBankAdapter({
  id: 'my-bank',
  label: 'اسم البنك',
  dateFormat: 'DD/MM/YYYY',      // أو 'MM/DD/YYYY' أو 'YYYY-MM-DD' أو 'auto'
  defaultCurrency: 'SAR',
  columns: {
    date: ['التاريخ', 'Date'],
    description: ['البيان', 'Description'],
    currency: ['العملة'],         // اختياري
  },
  amount: {
    kind: 'split',                // عمودان منفصلان
    debit: ['مدين'],
    credit: ['دائن'],
  },
  // أو عمود واحد مُشار:
  // amount: { kind: 'signed', amount: ['المبلغ'], direction: ['نوع العملية'] },
});
```

يلتقطه `import.meta.glob` تلقائياً في `src/adapters/index.ts`.

المحوّلات الحالية: `alrajhi`، `snb`، `chase`، `enbd`.

### كيف يختار الكاشف التلقائي

`detectAdapter` يعطي كل محوّل درجة = عدد الأعمدة التي تعرّف عليها، ويفوز الأعلى.
المقارنة **بالتساوي التام بعد التطبيع** لا بالاحتواء، حتى لا يبتلع `Amount`
عموداً أخص مثل `Debit Amount`.

عند الفشل يُرمى خطأ يحمل قائمة المرشّحين:

- `NoMatchingAdapterError` — لا يطابق أي محوّل
- `AmbiguousAdapterError` — تعادل محوّلان

كلاهما مصمَّم ليعرض للمستخدم قائمة اختيار يدوي، ويُمرَّر اختياره عبر
`importCsvText(text, { adapterId })`.

## معايرة توحيد أسماء التجار

الثابت الوحيد الذي يستحق المعايرة معلن في أعلى
`src/core/merchantNormalizer.ts`:

```ts
export const DEFAULT_SIMILARITY_THRESHOLD = 0.82;
```

- **رفعه** → مجموعات أنقى، لكن تفويت أشكال متباعدة لنفس التاجر
- **خفضه** → دمج أوسع، لكن خطر خلط تجّار مختلفين

التجميع يستخدم **ليفنشتاين مطوّرة من الصفر** (بلا مكتبة خارجية) مع خوارزمية
"قائد ومنضمّون" لمنع التسلسل الذي يبتلع تجّاراً متباعدين في مجموعة واحدة.

كل الأوصاف الأصلية محفوظة في `cluster.variants` — لا شيء يُفقد، ليتحقّق
المستخدم يدوياً في الواجهة لاحقاً.

**حدود معروفة ومقصودة:** `AMAZON` و`AMAZON PRIME` لا يتجمّعان، وكذلك `STC`
و`STC PAY` — لأنهما اشتراكان مستقلان بسعرين مختلفين. الفصل هنا مطلوب لا خطأ.

## محرك الكشف

نقطة دخول واحدة تأخذ مخرجات الاستيراد وتعيد المرشّحين مرتّبين:

```ts
import { detectSubscriptions } from './src/core/detectionEngine';

const { candidates, skipped } = detectSubscriptions(transactions);
```

كل مرشّح يحمل: `merchant`، `currency`، `transactions` (الأصل كاملاً)،
`periodicity`، `amountStability`، `effectiveStability`، `typicalAmount`،
`priceChange`، `freeTrial`، `confidence`، `suspicion`، و`flags`.
`skipped` يحمل المجموعات التي لم تبلغ ثلاث عمليات مع سببها.

### القياس بالأيام لا بالتقويم

فروق الأيام بين العمليات المتتالية هي كل شيء؛ أرقام أيام الشهر لا تدخل الحساب
إطلاقاً. لذلك يُكشف اشتراك كل 28 يوماً ينزلق عبر الشهور
(1 يناير → 29 يناير → 26 فبراير → 25 مارس) بنفس قوة اشتراك يخصم في نفس اليوم
من كل شهر — بل أنظف منه، لأن فروقه متطابقة بينما الشهر التقويمي يتراوح 28–31.

| وسيط الفروق (يوماً) | التصنيف |
| --- | --- |
| 6–8 | أسبوعي |
| 13–16 | نصف شهري |
| 27–32 | شهري |
| 85–95 | ربع سنوي |
| 175–190 | نصف سنوي |
| 355–375 | سنوي |

الحدود شاملة، وما بين المدايات يُصنَّف `irregular` بدل إجباره على أقرب خانة.
**الوسيط لا المتوسط**: فروق `[30,30,30,30,180]` متوسطها 60 يوماً (تصنيف خاطئ)
ووسيطها 30 (الصحيح).

### درجة الثقة ودرجة الاشتباه

```
evidence   = 0.45·انتظام + 0.35·ثبات + 0.20·عدد
confidence = بوابة‑الدورة × بوابة‑المبلغ × evidence

suspicion  = 0.35·استمرار + 0.35·صغر المبلغ + 0.30·ثبات النمط
```

الثقة تقول "هذا اشتراك"، والاشتباه يقول "وهذا ما يجب أن يراه المستخدم أولاً".
البوابتان تضربان لا تُجمعان لأنهما شرطان لازمان: نمط كل 45 يوماً لا يتجاوز 0.5
مهما كان منتظماً، وما لا سعر ثابت له تسقط ثقته إلى الصفر مهما كان إيقاعه
دقيقاً. التفصيل الكامل لكل وزن ولكل بوابة في التعليق أعلى `computeConfidence`.

**لا عتبة قبول/رفض في هذا الجزء.** كل مجموعة بلغت ثلاث عمليات تخرج بدرجتيها،
مرتّبةً بالاشتباه. أين يُقطع الخط قرار يُعايَر ببيانات حقيقية في الجزء 3.

### ثوابت المعايرة

كلها معلنة ومعلَّقة في أعلى ملفاتها، بلا أرقام سحرية منثورة:

| الثابت | الملف | المعنى |
| --- | --- | --- |
| `CYCLE_RANGES` | `periodicity.ts` | جدول التصنيف أعلاه |
| `MIN_TRANSACTIONS_FOR_PERIODICITY` | `periodicity.ts` | 3 — أقل ما يُسمّى تكراراً |
| `REGULARITY_COLLAPSE_SPREAD` | `periodicity.ts` | تشتت تنهار عنده درجة الانتظام |
| `AMOUNT_COLLAPSE_SPREAD` | `amountAnalysis.ts` | نظيره للمبالغ، أضيق منه عمداً |
| `PRICE_LEVEL_TOLERANCE` | `amountAnalysis.ts` | نصف قطر مستوى السعر الواحد |
| `MAX_LEVELS_RATIO` | `amountAnalysis.ts` | الحارس الذي يفصل المستويات عن الضجيج |
| `FREE_TRIAL_MAX_RATIO` | `amountAnalysis.ts` | 0.25 — حدّ التجربة المجانية |
| أوزان الثقة والاشتباه | `detectionEngine.ts` | مجموع كل ثلاثية = 1 |
| `SMALL_AMOUNT_FLOOR` / `LARGE_AMOUNT_CEILING` | `detectionEngine.ts` | نافذة "صغر المبلغ" |

### حدود معروفة ومكشوفة

- **الإيجار الشهري الثابت** يحصل على ثقة عالية، وهذا صحيح رياضياً: هو رسم
  دوري بمبلغ ثابت. لا توجد في بيانات الجزء 1 أي إشارة تفصل "رسم دوري" عن
  "اشتراك برمجي". درجة الاشتباه تخفّفه (المبلغ كبير فيهبط في الترتيب) ولا
  تحلّه. المسارات الثلاثة المقترحة للحلّ موثّقة في رأس `detectionEngine.ts`،
  والقرار للجزء 3.
- **البقالة الأسبوعية المتغيّرة** تُستبعد تلقائياً باختبار ثبات المبلغ وحده،
  بلا قاعدة خاصة بها.
- **المبالغ تُقارن بلا تحويل عملة**، فتبدو مجموعة بالدولار "أصغر" مما هي في
  درجة الاشتباه. النافذة معايَرة بالريال السعودي.
