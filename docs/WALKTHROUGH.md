# شرح المستودع ملفاً بملف

هذا الملف يشرح **كل ملف** في مشروع رصيد بجملة أو جملتين، بحيث تفهم بنية
المشروع كاملة بقراءته وحده — بلا فتح أي كود.

اقرأه بالترتيب: الطبقات مرتّبة كما تمرّ عليها البيانات فعلاً، من بايتات الملف
إلى الشاشة.

---

## نظرة عامة في ثلاثين ثانية

```
ملف CSV  →  src/adapters  →  src/core  →  src/ui  →  الشاشة
            (يفهم البنك)    (يفكّر)      (يعرض)
```

- **`src/core/`** — كل المنطق، دوال نقية بلا React وبلا متصفح. قابلة للاختبار
  في Node بمعزل تام.
- **`src/adapters/`** — يعرف كيف يقرأ ملف كل بنك. ملف واحد لكل بنك.
- **`src/ui/`** — يعرض فقط. لا منطق كشف فيه إطلاقاً.
- **`eval/`** — يقيس كم هذا كلّه ناجح، بأرقام قابلة لإعادة الإنتاج.

القاعدة التي تحكم كل شيء: **`src/core` لا يستورد شيئاً من `src/ui` أبداً.**

## 1. طبقة النصّ والأدوات الأساسية

| الملف | ماذا يفعل |
| --- | --- |
| `src/core/types.ts` | العقد بين كل أجزاء المشروع: نوع `Transaction` (تاريخ ISO، مبلغ موجب دائماً، اتجاه، عملة) وأنواع صفوف CSV. كل شيء آخر مبنيّ على هذا الملف. |
| `src/core/errors.ts` | شجرة الأخطاء المتوقّعة (`CsvParseError`، `AdapterDetectionError`…) حتى تميّز الواجهة بين خطأ تعرضه للمستخدم وخطأ برمجي. |
| `src/core/text.ts` | تطبيع النصوص العربية والإنجليزية: تحويل الأرقام الهندية (٥٦ ← 56)، حذف التشكيل والمحارف الخفية، توحيد الهمزات (أ إ آ ← ا). بدونه لا يتطابق شيء. |
| `src/core/stats.ts` | الوسيط ومتوسط الانحراف المطلق حوله. **لا متوسط حسابي في أي قرار** — لأن قيمة شاذة واحدة تفسده. |

## 2. قراءة الملف

| الملف | ماذا يفعل |
| --- | --- |
| `src/core/csv.ts` | يفكّ ترميز الملف (UTF-8 أولاً بصرامة، ثم `windows-1256` للملفات العربية القديمة) ويحلّله إلى جدول، مكتشفاً الفاصل تلقائياً (`,` أو `;` أو تبويب). |
| `src/core/dateParser.ts` | يحوّل أي شكل تاريخ إلى `YYYY-MM-DD`، ويحسم الالتباس الشهير بين `03/04/2024` كـ 3 أبريل أو 4 مارس بالاعتماد على صيغة البنك المصرَّح بها لا على التخمين. |
| `src/core/amountParser.ts` | يفكّ خلايا المبالغ الفوضوية: `"1,234.50 ر.س"`، `"(45.00)"` للسالب، `"250 DR"`، الأرقام الهندية، والنمط الأوروبي `"1.234,56"`. |
| `src/core/importCsv.ts` | يربط الخطوات السابقة: بايتات → نصّ → جدول → اختيار المحوّل → `Transaction[]`. نقطة الدخول القديمة التي يستخدمها التقييم. |

## 3. تنسيقات البنوك

| الملف | ماذا يفعل |
| --- | --- |
| `src/adapters/types.ts` | واجهة المحوّل البنكي: كيف يتعرّف على ترويسة ملف (`match`) وكيف يحوّل صفوفه (`parse`)، ونوع الوصف التعريفي الذي يكفي لبناء بنك جديد. |
| `src/adapters/createBankAdapter.ts` | المصنع الذي يحوّل وصفاً تعريفياً (أسماء الأعمدة وصيغة التاريخ) إلى محوّل عامل. **كل منطق التحويل المشترك يعيش هنا مرة واحدة.** |
| `src/adapters/index.ts` | سجلّ المحوّلات: يلتقط أي ملف `*.adapter.ts` تلقائياً عبر `import.meta.glob`، ويختار المحوّل المناسب لملف المستخدم (`detectAdapter`) بمن يتعرّف على أكبر عدد من الأعمدة. |
| `src/adapters/alrajhi.adapter.ts` | مصرف الراجحي: ترويسة عربية، تاريخ `DD/MM/YYYY`، عمودان منفصلان للمدين والدائن، ورمز `ر.س`. |
| `src/adapters/snb.adapter.ts` | البنك الأهلي السعودي: ترويسة عربية، تاريخ ISO، عمود مبلغ واحد يحمل رمز العملة داخله، وعمود "نوع العملية" يتقدّم على إشارة الرقم. |
| `src/adapters/chase.adapter.ts` | النمط الأمريكي (Chase / Bank of America): تاريخ `MM/DD/YYYY`، رمز `$` داخل الخلية، وأقواس للسالب. |
| `src/adapters/enbd.adapter.ts` | بنك الإمارات دبي الوطني: ترويسة إنجليزية لكن تاريخ `DD/MM/YYYY` (خلافاً للأمريكي)، وعمودان للمبلغ. |

## 4. توحيد أسماء التجّار

| الملف | ماذا يفعل |
| --- | --- |
| `src/core/merchantNormalizer.ts` | يحوّل `POS NETFLIX.COM*4423` و`NETFLIX.COM AMSTERDAM NL` إلى تاجر واحد اسمه `NETFLIX`: ينظّف الضجيج (أرقام مرجعية، مدن، رموز نقاط بيع)، ثم يقيس التشابه بـ **ليفنشتاين مطوّرة هنا من الصفر**، ثم يجمّع المتشابه. بدون هذه الخطوة لا يرى المحرك أي تكرار. |

## 5. محرك الكشف

| الملف | ماذا يفعل |
| --- | --- |
| `src/core/periodicity.ts` | يجيب: هل تتكرّر هذه العمليات على إيقاع ثابت؟ يقيس **فروق الأيام** بين الخصوم (لا أرقام أيام الشهر)، ويصنّف وسيطها عبر جدول `CYCLE_RANGES` إلى أسبوعي/شهري/سنوي… ويعطي درجة انتظام. هنا يُكشف اشتراك الـ28 يوماً المنزلق. |
| `src/core/amountAnalysis.ts` | يجيب ثلاثة أسئلة عن المبالغ: هل المبلغ ثابت؟ هل انقسم إلى مستويين بحدّ زمني (زيادة سعر)؟ وهل كان أول رسم رمزياً ثم تحوّل (تجربة مجانية)؟ |
| `src/core/detectionEngine.ts` | القلب: يجمّع العمليات في مجموعات تاجر، ويشغّل الدورية وتحليل المبالغ، ثم يحسب **درجة الثقة** (كم يشبه هذا اشتراكاً؟) و**درجة الاشتباه** (كم يُرجَّح أن صاحبه نسيه؟). **لا يقرّر عتبة قبول** — يترك ذلك للجزء التالي. |
| `src/core/decision.ts` | قرارات العرض: أين تُقطع العتبة (0.60، معايَرة من مسح عتبات في التقييم)، ومستويات الثقة المعروضة، وقائمة الفئات غير الاشتراكية (إيجار، قسط، راتب) التي تُخرَج من المجاميع مع بقائها معروضة، وتحويل كل دورة إلى **كلفة شهرية مقارَنة**. |
| `src/core/analyze.ts` | خط المعالجة كاملاً في دالة واحدة: بايتات → نتيجة جاهزة للعرض، مع تبليغ التقدّم بعد كل مرحلة. هذا ما يستدعيه العامل. |

| `src/ui/ErrorView.tsx` | شاشة الخطأ ومعها مخرج: تعرض الأعمدة التي وجدها في ملفك، وقائمة البنوك لاختيار بنكك يدوياً وإعادة المحاولة. |
| `src/ui/cancellationList.ts` | يبني ملف "قائمة الإلغاء" النصّي (دالة نقية قابلة للاختبار) ثم ينزّله عبر رابط `blob:` محلي — بلا مغادرة الجهاز. |
| `src/ui/styles.css` | كل الأنماط: خطوط النظام فقط (لا خط ويب = لا طلب شبكة)، وخصائص منطقية (`margin-inline-start`) تجعل التخطيط ينقلب مع RTL بلا ورقة ثانية، وتحويل الجدول إلى بطاقات على الهاتف. |
| `src/vite-env.d.ts` | تعريفات أنواع Vite (`import.meta.glob` وغيره) لمحرّك TypeScript. |
